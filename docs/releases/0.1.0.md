# Fleet 0.1.0

The first release of Fleet: a macOS workspace for running installed coding-agent CLIs side by side. A Rust daemon, `fleet-daemon`, owns every agent process and its PTY, and the app attaches to it as a client. Closing the window detaches the app and leaves the agents running.

This is a 0.1.0 prototype, not a finished app. It is the first milestone: one project, two live agent sessions, reliable terminal input and resizing, and reattaching without restarting agents.

## Requirements

- macOS 14 Sonoma or newer.
- Apple Silicon (`arm64`). There is no Intel build and no universal binary yet.
- At least one agent CLI on `PATH`: Claude Code, Codex, Cursor Agent, Gemini CLI, or OpenCode. A login shell and a custom command also work, so Fleet runs with no agent installed.

## Install

1. Open `Fleet-0.1.0-macos-arm64.dmg` and drag **Fleet** into **Applications**.
2. The build is ad-hoc signed and not notarized, so macOS quarantines the download. The first launch needs **right-click → Open**, or:

   ```sh
   xattr -dr com.apple.quarantine /Applications/Fleet.app
   ```

3. Fleet runs the `fleet-daemon` bundled in `Fleet.app/Contents/Resources`, so the release needs no separate daemon install.

Verify the download before opening it:

```sh
shasum -a 256 -c Fleet-0.1.0-macos-arm64.dmg.sha256
```

## What is in 0.1.0

- **Two live terminal panes**, stacked or side by side, each attached to its own agent session with its own working directory.
- **A session sidebar** with project header, filters, session rows, context menus, and daemon status.
- **Agent presets** for Claude Code, Codex, Cursor Agent, Gemini CLI, OpenCode, a login shell, and a custom command. Each agent uses its own credentials and talks to its model provider directly.
- **A context panel** that follows the focused agent's working tree, shows git status and the diff for the file the agent just changed, and can open a shell for Helix.
- **New-agent sheet** with preset, working directory, and optional name.
- **Settings** for appearance, terminal font, cursor, line spacing, scrollback, the launch split, stop confirmation, the new-agent folder, the socket path, and daemon auto-start.
- **Detach and reattach.** Quit the app and relaunch: running agents are still there, because the daemon kept their PTYs.
- **Reconnect flow** and an empty state when the daemon is unavailable.

## Known limitations

- Ad-hoc signed and not notarized. Gatekeeper blocks the first launch until you right-click Open or remove the quarantine attribute.
- Apple Silicon only.
- One project at a time. No project switching and no worktree management.
- Session state is memory-only. Sessions live as long as the daemon does; nothing is persisted across daemon restarts.
- There is no terminal state snapshot yet. Attaching to an existing session replays the retained output, so a long-running TUI rebuilds only as much of the screen as that backlog covers.
- Fork starts a new process with the same program and working directory. It does not fork the agent's conversation.
- The context panel reads git status and file diffs. It does not stage or commit.
- No session-list-changed event: sessions created by another client appear after reconnecting or relaunching.
- Dropping files onto a terminal pane does nothing yet ([#47](https://github.com/nsrul/fleet/issues/47)). Type or paste the path instead.
